# mcp-server-runtime Specification

## Purpose

Определяет, как MCP-сервер `mcp-moex` регистрирует инструменты, описывает их параметры, возвращает результаты и ошибки, каким образом запускается локально и как проверяется клиентом. Это контракт между сервером и внешним ИИ-агентом.

## Requirements

### Requirement: Регистрация инструментов
Сервер SHALL публиковать через `list_tools` по умолчанию ровно три инструмента: `search_securities`, `get_current_price` и `get_price_history`. Каждый инструмент MUST иметь текстовое описание, объясняющее для чего он нужен и когда его применять, и JSON-схему входных параметров с типами, описаниями, допустимыми значениями перечислений, значениями по умолчанию и границами. Все три инструмента MUST быть помечены как только читающие (`readOnlyHint`), сервер SHALL NOT выполнять никаких действий, изменяющих внешние системы. Только при явном включении режима расписания (флаг `--watch-db`) сервер SHALL дополнительно публиковать шесть инструментов расписания (см. возможность `moex-price-watch`): они изменяют лишь локальное хранилище сервера, не помечены как только читающие и не относятся к трём инструментам чтения, чьё поведение режим не меняет.

#### Scenario: Клиент запрашивает список инструментов
- **WHEN** клиент вызывает `list_tools` у сервера, запущенного без `--watch-db`
- **THEN** ответ содержит три инструмента с именами `search_securities`, `get_current_price`, `get_price_history`
- **AND** у каждого есть описание и `inputSchema` с описанием каждого параметра
- **AND** у каждого установлен признак `readOnlyHint = true`

#### Scenario: Описание подсказывает порядок использования
- **WHEN** агент читает описания инструментов
- **THEN** описание `get_current_price` и `get_price_history` указывает, что тикер (`secid`) следует получать через `search_securities`, если пользователь назвал бумагу по названию или ISIN

#### Scenario: Режим расписания включён
- **WHEN** клиент вызывает `list_tools` у сервера, запущенного с `--watch-db`
- **THEN** ответ содержит три инструмента чтения с `readOnlyHint = true` и шесть инструментов расписания без этого признака

### Requirement: Формат результата инструмента
Успешный вызов инструмента SHALL возвращать структурированный результат (`structuredContent`), соответствующий выходной JSON-схеме инструмента, и дублировать его текстовым JSON в `content` для клиентов без поддержки структурированного вывода. Все поля результата MUST иметь понятные имена и явные единицы измерения; сырые массивы `columns` и `data` из ISS SHALL NOT попадать в результат.

#### Scenario: Успешный вызов
- **WHEN** клиент вызывает любой из инструментов с корректными аргументами
- **THEN** результат не помечен как ошибка
- **AND** содержит `structuredContent`, соответствующий схеме
- **AND** текстовый `content` содержит тот же JSON

### Requirement: Ошибки инструмента
Сервер SHALL сообщать об ошибках как о результате инструмента, помеченном как ошибка (`isError = true`), с понятным для LLM текстом: что произошло и что делать дальше. Сервер MUST NOT завершаться аварийно и MUST NOT раскрывать в тексте ошибки внутренние трассировки. Ошибки SHALL охватывать как минимум: неизвестный тикер, неподдерживаемый класс инструмента, некорректные аргументы, недоступность ISS (таймаут, сетевая ошибка, ответ не 2xx), слишком большой запрошенный объём данных.

#### Scenario: ISS недоступен
- **WHEN** запрос к ISS завершается таймаутом или сетевой ошибкой
- **THEN** инструмент возвращает ошибку с сообщением о временной недоступности Московской биржи и рекомендацией повторить позже
- **AND** сервер продолжает принимать последующие вызовы

#### Scenario: Некорректные аргументы
- **WHEN** клиент вызывает инструмент с аргументами, нарушающими схему (например, отсутствует обязательный параметр)
- **THEN** вызов завершается ошибкой с указанием проблемного параметра

### Requirement: Локальный запуск и транспорты
Сервер SHALL запускаться командой `mcp-moex` без каких-либо обязательных настроек, ключей или учётных данных. По умолчанию сервер MUST использовать транспорт `stdio`. По явному указанию сервер SHALL работать по Streamable HTTP, при этом MUST принимать соединения только на loopback-адресе `127.0.0.1`. Сервер MUST допускать запуск клиентом в виде `uv run --directory <путь к проекту> mcp-moex`. Сервер SHALL принимать необязательный аргумент `--watch-db <путь>`, включающий режим расписания с хранилищем по этому пути (с любым из транспортов); без него сервер MUST NOT создавать и открывать файлов хранилища.

#### Scenario: Запуск по умолчанию
- **WHEN** агент запускает `mcp-moex` без аргументов как подпроцесс
- **THEN** сервер общается с агентом по `stdio` и не открывает сетевых портов
- **AND** не создаёт файлов на диске

#### Scenario: Запуск по HTTP
- **WHEN** сервер запущен с указанием транспорта Streamable HTTP
- **THEN** он слушает только `127.0.0.1`
- **AND** недоступен с других сетевых интерфейсов

#### Scenario: Запуск в режиме расписания
- **WHEN** клиент запускает `mcp-moex --watch-db <путь>` по `stdio`
- **THEN** сервер публикует инструменты расписания и хранит данные по указанному пути

### Requirement: Логирование не мешает протоколу
При транспорте `stdio` сервер MUST NOT писать в стандартный вывод ничего, кроме сообщений протокола MCP. Все журналы и диагностика SHALL направляться в стандартный поток ошибок.

#### Scenario: Журналирование во время вызова
- **WHEN** сервер обрабатывает вызов инструмента по `stdio` и пишет диагностику
- **THEN** диагностика попадает в stderr
- **AND** stdout содержит только корректные сообщения протокола

### Requirement: Проверка смоук-клиентом
Проект SHALL включать смоук-клиент, использующий MCP SDK: он запускает сервер по `stdio`, вызывает `list_tools` и вызывает каждый из трёх инструментов на реальных данных, печатает результаты и завершается ненулевым кодом, если любой шаг не удался.

#### Scenario: Успешная проверка
- **WHEN** запущен смоук-клиент при доступном ISS
- **THEN** он выводит список инструментов и результаты вызовов поиска, текущей цены и истории
- **AND** завершается с кодом 0

#### Scenario: Сбой проверки
- **WHEN** любой из вызовов возвращает ошибку или сервер не запускается
- **THEN** смоук-клиент завершается с ненулевым кодом и указывает, какой шаг не удался
