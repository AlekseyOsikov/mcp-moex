# moex-security-search Specification

## Purpose

Позволяет агенту найти бумагу на Московской бирже по названию, тикеру или ISIN и получить её `secid` для остальных инструментов, не угадывая тикеры по памяти и не получая шум в виде индикаторов, снятых с торгов бумаг и десятков облигаций одного эмитента.

## Requirements

### Requirement: Поиск бумаги
Инструмент `search_securities` SHALL принимать параметры `query` (непустая строка: название, тикер или ISIN), `asset_type` (`any`, `stock`, `bond`, `fund`, `index`; по умолчанию `any`) и `limit` (целое от 1 до 20; по умолчанию 10) и возвращать список найденных бумаг. Каждый элемент MUST содержать `secid`, `name`, `isin` (или `null`), `asset_type` и `board` (основную торговую площадку). Результат MUST содержать `count` и признак `truncated`.

#### Scenario: Поиск по названию
- **WHEN** агент вызывает `search_securities` с `query = "Сбербанк"` и `asset_type = "stock"`
- **THEN** среди результатов есть `SBER` и `SBERP` с `asset_type = "stock"`
- **AND** в результатах нет облигаций, индексов и фондов

#### Scenario: Поиск по ISIN
- **WHEN** агент вызывает `search_securities` с `query = "RU0009029540"`
- **THEN** первым элементом результата является `SBER`

#### Scenario: Пустой запрос
- **WHEN** агент вызывает `search_securities` с пустым или состоящим из пробелов `query`
- **THEN** вызов завершается ошибкой валидации

### Requirement: Только торгуемые бумаги
Результаты поиска SHALL включать только бумаги, по которым идут торги на данный момент. Снятые с торгов и неторгуемые записи (в том числе исторические дубли тикеров на устаревших площадках) MUST NOT попадать в результат.

#### Scenario: Дубли исторических тикеров
- **WHEN** агент ищет бумагу, у которой в ISS есть неторгуемые исторические записи с тем же ISIN
- **THEN** в результате присутствует только торгуемая запись

### Requirement: Классы активов
Параметр `asset_type` SHALL определять класс искомых бумаг: `stock` — акции и депозитарные расписки; `bond` — облигации; `fund` — паи биржевых и иных фондов, торгуемых на бирже; `index` — индексы. Значение `any` SHALL охватывать все четыре класса. Фьючерсы, опционы, валюта, драгоценные металлы и прочие классы MUST NOT возвращаться ни при каком значении. Каждый элемент результата MUST содержать нормализованный `asset_type`, а не внутреннюю группу ISS.

#### Scenario: Ограничение классом фондов
- **WHEN** агент вызывает `search_securities` с `query = "золото"` и `asset_type = "fund"`
- **THEN** результат содержит золотые фонды (например, `TGLD`) с `asset_type = "fund"`
- **AND** не содержит индексов и расчётных показателей

#### Scenario: Без ограничения классом
- **WHEN** агент вызывает `search_securities` с `asset_type = "any"`
- **THEN** результаты могут содержать акции, облигации, фонды и индексы, но не содержат фьючерсов и валютных инструментов

### Requirement: Исключение расчётных показателей
Результаты поиска MUST NOT включать расчётные показатели, которые нельзя купить или продать: индикативную стоимость паёв (iNAV, площадка `INAV`) и фиксинги (площадка `INPF`). Для класса `index` результат SHALL содержать только индексы, публикуемые на площадках `SNDX` и `RTSI`.

#### Scenario: Запрос по фонду с расчётным показателем
- **WHEN** агент ищет `TGLD`
- **THEN** результат содержит фонд `TGLD`
- **AND** не содержит `TGLDA` и `TGLDB` (iNAV)

### Requirement: Порядок результатов
Если значение `query` совпадает с `secid` или ISIN бумаги без учёта регистра, такая бумага SHALL быть первой в результате. Остальные результаты SHALL следовать в порядке выдачи ISS.

#### Scenario: Точное совпадение тикера
- **WHEN** агент вызывает `search_securities` с `query = "sber"`
- **THEN** первым элементом результата является `SBER`

### Requirement: Ограничение объёма
Сервер SHALL возвращать не более `limit` элементов. Если найдено больше, `truncated` MUST быть `true`, чтобы агент знал о необходимости уточнить запрос или сузить `asset_type`. Отсутствие совпадений SHALL считаться штатным результатом: пустой список, `count = 0`, без ошибки.

#### Scenario: Совпадений больше лимита
- **WHEN** агент вызывает `search_securities` с `query = "банк"`, `asset_type = "any"` и `limit = 5`
- **THEN** в результате ровно 5 элементов
- **AND** `truncated = true`

#### Scenario: Ничего не найдено
- **WHEN** агент вызывает `search_securities` с запросом, которому ничего не соответствует
- **THEN** результат содержит пустой список и `count = 0`
- **AND** вызов не помечен как ошибка
