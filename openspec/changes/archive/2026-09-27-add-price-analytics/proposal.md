# Proposal

## Why

Агент умеет получить историю цен, но не умеет её надёжно осмыслить: посчитать просадку
или волатильность по сотням свечей в контексте модели — значит тратить токены и
рисковать арифметикой, а сравнить бумагу с рынком («обгоняла ли она индекс за год») или
две бумаги между собой по двум длинным рядам вручную практически невозможно. Нужны
инструменты, которые считают код, а не модель. Они принимают историю цен, уже
полученную от `get_price_history`, и возвращают проверяемые числа, таблицу по периодам и
готовый текст. Клиент (Telegram-бот) использует их в цепочке «найти тикер → получить
историю → посчитать метрики → сравнить», а данные между шагами передаёт дословно
(изменение в репозитории клиента).

## What Changes

- Три новых инструмента только для чтения, без обращений к сети и без состояния:
  - `compute_price_metrics(history)` — метрики одной бумаги за период: изменение цены,
    годовая волатильность, максимальная и текущая просадка, таблица изменений по каждой
    свече (по месяцам, неделям, дням).
  - `compare_with_benchmark(history, benchmark_history)` — сравнение бумаги с эталонным
    индексом по общим датам: изменение обоих, разница в процентных пунктах, бета,
    корреляция, просадки, таблица по периодам. Для вопроса «обгоняла ли бумага рынок».
  - `compare_securities(history_a, history_b)` — сравнение двух бумаг между собой (акции
    и фонды, не индексы): изменение обеих, разница `a − b` в процентных пунктах,
    корреляция, просадки, таблица по периодам. Беты нет: у пары бумаг она смысла не имеет.
  Выбор между двумя сравнениями однозначный: если участвует индекс, вызывается
  `compare_with_benchmark`, если две бумаги — `compare_securities`; описания инструментов
  говорят об этом прямо.
- Входные параметры (`history`, `benchmark_history`, `history_a`, `history_b`) — это
  результат `get_price_history` целиком, без преобразований. Сервер проверяет входные
  данные: история не должна быть усечена, свечи должны быть согласованы со сводкой (число,
  начальная и конечная цена, минимум и максимум), цены положительны, интервал не часовой.
- Результат каждого инструмента содержит структурированные числа, список предупреждений
  `notes` и готовый шаблонный русский текст `text` (без LLM), где числа совпадают с
  числами структуры, а формулировки говорят об «изменении цены», а не о «доходности», и
  содержат оговорки: без дивидендов и купонов, прошлое не гарантирует будущее, не
  индивидуальная рекомендация.
- Изменение цены за период считается так, что согласуется со `summary.change_pct` из
  `get_price_history`: первая свеча от `open`, остальные от предыдущего `close`.
- Оба сравнения используют общее ядро: выравнивание по датам, единые правила базы,
  корреляции и просадок. Облигации в сравнениях не поддерживаются (цена в процентах от
  номинала без накопленного купонного дохода); метрики одной облигации допустимы с
  предупреждением.
- **BREAKING**: нет. Три существующих инструмента и режим расписания не меняются;
  меняется формулировка «по умолчанию ровно три инструмента» на шесть.

## Capabilities

### New Capabilities
- `moex-price-analytics`: метрики по одной бумаге, сравнение с эталонным индексом и
  сравнение двух бумаг по истории, полученной от `get_price_history`, с проверкой
  входных данных, предупреждениями и шаблонным текстом итога.

### Modified Capabilities
- `mcp-server-runtime`: регистрация инструментов (шесть по умолчанию, все только для
  чтения) и смоук-клиент (проверяет и новые инструменты).
- `moex-price-watch`: в сценарии «Режим расписания включён» «три инструмента чтения»
  становятся шестью (поведение режима расписания не меняется, правится только счёт).

## Impact

- Код: новый чистый модуль расчётов `src/mcp_moex/analytics/` (метрики, выравнивание
  рядов, общее ядро сравнений, шаблон текста), `src/mcp_moex/tools/analytics.py` с
  описаниями трёх инструментов, правки `server.py` (регистрация, `_guard`, `INSTRUCTIONS`,
  часы для признака незакрытой свечи) и `models.py` (результаты), `errors.py` (доменные
  ошибки с текстом для LLM).
- Зависимости: только стандартная библиотека (`statistics`, `math`); новых пакетов нет.
- Сеть и диск: инструменты не обращаются ни к ISS, ни к файлам.
- Тесты: чистые функции на рукописных рядах и на существующих фикстурах свечей SBER и
  IMOEX; проверки-тождества (индекс против самого себя, бумага против самой себя).
  Правки существующих: `tests/test_server.py` (счёт инструментов), `tests/fake_mcp_server.py`
  и `tests/test_smoke_client.py` (фейковый сервер знает только три инструмента),
  `scripts/smoke_client.py` (ожидаемый набор и новые шаги).
- Документация: `README.md`, `CLAUDE.md` (говорят о трёх инструментах).
- Смежное изменение (репозиторий бота, создаётся отдельно): бот отдаёт модели три
  инструмента, хранит результаты вызовов в памяти сессии и подставляет их в параметры
  `history`/`benchmark_history`/`history_a`/`history_b` по ссылке. Схемы этих параметров
  и текст ошибок — шов между двумя изменениями.
